## 파이썬 패키지

코드가 실제로 `import` 하는 것만 적었습니다.

**2026-09-25 서버에서 읽은 실측값입니다.** 파이썬은 `3.9.18` 입니다.

`sklearn` 이 가장 급합니다. `RandomForestClassifier` 와 `SVC` 의 기본값이 버전 사이에
바뀌었고, 1차 지표 칸의 RF 점수 고유값이 10~46개뿐이라 트리 구성이 조금만 달라져도
동점 구조가 바뀝니다(동점 폭 0.105~0.162). **버전이 없으면 그 표는 재현 불가입니다.**

## 계산 자원

이 코드가 실제로 돈 기계입니다. 참고값입니다.

| | |
|---|---|
| CPU | 32코어 |
| 메모리 | 62G · **스왑 0** |
| 디스크 | 7T SSD |

**스왑이 0이면 빈 메모리가 마를 때 완충이 없습니다.** 커널이 페이지 캐시를 버리고,
그때부터 모든 파일 읽기가 디스크로 가 부하가 치솟습니다. 접속까지 막힙니다.

동시 실행 수는 코어가 아니라 **빈 메모리**가 정합니다. 32코어·62G 에서 실측 —

| 동시 수 | 부하 | 빈 메모리 | |
|---|---|---|---|
| 8 | 5~8 | 47~53G | 안정 |
| 14 (사슬 2개) | 10~13 | 46~48G | 안정 |
| 42 (사슬 3개 겹침) | 59~93 | 19G | 붕괴 · 접속 불가 |

2 → 3 에서 선형이 아니라 **절벽**이었습니다. `buff/cache` 가 22G → 5G 로 무너지면서
모든 파일 읽기가 디스크로 갔습니다.

## 주의

`1_dmr/steps/` 과 `2_train/steps/` 의 스크립트는 **불러오면 그 자리에서 실행**되던 것이라
`import` 를 거부하는 가드를 넣었습니다. 실행은 `python <파일>` 로만 합니다.

시험할 때는 `config.conf` 의 `METH_ROOT` 를 **빈 임시 폴더**로 바꾸고 하십시오.
그러지 않으면 실제 산출물을 덮어씁니다.

## 어느 운영체제에서 도는가: **리눅스 전용이다**

윈도우에서는 **경로를 고치고 코드를 읽을 수만 있다. 돌아가지 않는다.**
고쳐서 되는 문제가 아니라 쓰는 도구가 리눅스 것이다.

| 무엇 | 어디에 | 왜 윈도우에서 안 되나 |
|---|---|---|
| `flock` | 7개 셸 | 중복 실행 막는 파일 잠금. 윈도우에 없다 |
| `/proc/<pid>/smaps_rollup` | `메모리규칙.sh` 등 4개 | 메모리 실측. 리눅스 전용 파일계 |
| `pgrep`·`pkill` | 4개 | 프로세스 찾기 |
| `setsid`·`nohup` | 드라이버들 | 떼어 놓고 돌리기 |
| `du`·`df -BG` | 3개 | 디스크 재기 |
| bismark · bowtie2 · samtools | `2_train/steps/03` 등 | 리눅스 빌드만 쓴다 |

또 셸이 `python` 을 부른다(`python3` 아님): **conda 환경이 PATH 에 있어야 한다.**
서버에서는 `export PATH=$HOME/anaconda3/envs/myenv/bin:$PATH` 로 맞춘다.

WSL 에서는 돌 것으로 보이지만 **해 보지 않았다.** 확인한 것은 이 서버뿐이다.
맥에서는 `/proc` 이 없어 운영·감시 스크립트가 안 돈다. 그 스크립트들은
이 저장소에 넣지 않았습니다(결과와 무관). 계산 단계는 돌 수 있습니다.
