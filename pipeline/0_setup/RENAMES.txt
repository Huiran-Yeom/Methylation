 Output names: this repository writes English names throughout
════════════════════════════════════════════════════════════════════
 분석을 돌릴 때 우리 내부 트리는 산출물 폴더·파일 이름에 한글을 썼습니다.
 이 저장소의 코드는 **영어 이름으로 쓰고 영어 이름으로 읽습니다** — 쓰는 쪽과
 읽는 쪽을 함께 고쳤습니다. 처음부터 돌리는 사람은 한글을 볼 일이 없습니다.

 While the analysis was run, our internal tree used Korean names for output
 folders and files. This repository writes *and* reads English names —
 writers and readers were changed together. A fresh run never sees Korean.

   내부 트리 (분석 당시)            이 저장소 (공개본)
   ──────────────────────────────  ──────────────────────────────────────
   results/판/                      results/panels/
   sample_data/판/                  sample_data/panels/
   j_panel_dmr<GEN>_판/             j_panel_dmr<GEN>_panels/
   bl200_d10_세포주/                bl200_d10_cellline/
   _출처.txt                        _origin.txt
   설정_스냅샷.txt                  config_snapshot.txt
   배경매핑_<판>.csv                background_map_<판>.csv
   y_prob_all_<판>_모든조합.csv     y_prob_all_<판>_all_combos.csv
   _보완/panel_jsd보완_n200.csv     _supplement/panel_jsd_supplement_n200.csv
   ~/tmp/결과/                      ~/tmp/results/
   ~/tmp/락/                        ~/tmp/lock/   (하위 검증/ -> val/, 그만 -> STOP)

 왜 이것이 「그냥 찾아 바꾸기」가 아닌가
   이름 하나하나에 **쓰는 곳과 읽는 곳**이 있습니다. 한쪽만 고치면 프로그램은
   죽지 않고 그 파일만 못 찾은 채 끝까지 돕니다. 채점이 결측을 평균으로 메워
   AUC 0.500 이 나옵니다. 그래서 이름마다 쓰는 곳·읽는 곳을 짝지어 바꾸고,
   selfcheck.sh 9번 묶음이 「경로에 한글이 남았나」를 기계로 훑습니다.
   결함을 일부러 되넣어 FAIL 이 뜨는 것까지 확인했습니다.

 우리 내부 결과와 대조하려면
   내부 트리에 이미 쌓인 산출물은 한글 이름입니다. 공개본 코드로 그것을 읽으려면
   폴더 계층만 심링크로 이어 줍니다 (데이터를 복사하거나 옮기지 않습니다):
     ln -s "판"  <뿌리>/results/panels
   파일 「이름」 이 다른 것(y_prob_all_…_모든조합.csv 등)은 심링크로 안 되므로,
   비교 스크립트에서 이름을 맞춰 md5 를 대조했습니다.

 로그·잠금 이름
   ~/tmp/lock/ 은 각 드라이버가 스스로 mkdir 합니다. 내부 트리에서는 감시
   스크립트가 만들어 주고 있었는데 그 스크립트는 이 저장소에 없습니다 —
   그대로 두면 받아서 돌리는 사람은 첫 flock 에서 실패합니다(2026-09-29 수정).
